# SecurePayload — Agent Guide

Library: `sk8dvlpr/securepayload` v3.1.0 | Protocol version: `4`

## Before Any Code Change

1. Read `.claude/skills/securepayload/securepayload-development/SKILL.md`
2. Run GitNexus impact analysis on symbols you will edit — MCP `impact({target: "symbolName", direction: "upstream", repo: "SecurePayload"})` when exposed, else CLI fallback (see GitNexus section below)
3. If touching verify/build/sign/AEAD/replay: read `securepayload-security-review` skill
4. Run `composer test` and `composer stan` before considering work complete
5. Run change detection before commit — MCP `detect_changes({scope: "compare", base_ref: "main", repo: "SecurePayload"})` when exposed, else CLI fallback (see GitNexus section below)

## Security Invariants (Never Break)

- Server derives `method`/`path`/`query` from request input — **NOT** `X-Canonical-Request`
- Replay key excludes timestamp; TTL = `replayTtl + clockSkew`
- HMAC signs plaintext in `both` mode
- All secret/signature comparisons use `hash_equals`
- `signAlg` determined by server config (anti-downgrade) — applies to request **and** response
- `deriveKeys` and `bindHeaders` must match on client and server
- Ed25519 request: client keypair; Ed25519 response: server keypair (`ed25519PublicKeyServerB64` / `ed25519SecretKeyServerB64`)
- Hybrid PQ (`hybrid-mldsa44-ed25519`): requires injected `pqSigner`; wire = Ed25519‖ML-DSA

## Commands

- Install: `composer install`
- Full test: `composer test` (= `vendor/bin/phpunit`)
- Single suite: `vendor/bin/phpunit --testsuite Unit|Integration|Security|Conformance`
- Single file: `vendor/bin/phpunit tests/Unit/SecurePayloadTest.php`
- Single test: `vendor/bin/phpunit --filter testName`
- Static analysis: `composer stan` (= `vendor/bin/phpstan analyse -c phpstan.neon`; level 5, path `src`)
- Syntax lint (CI only — no composer script, no phpcs/php-cs-fixer/psalm): `find src -name "*.php" -print0 | xargs -0 -n1 php -l`
- Regenerate protocol fixtures (needs ext-sodium; deterministic, fixed clock/nonce): `php tools/generate-protocol-fixtures.php`
- Reindex GitNexus: `node .gitnexus/run.cjs analyze`

## Testing & CI quirks

- 4 test suites in `tests/` — `Unit`, `Integration`, `Security`, `Conformance` (48 test files). No network/service dependencies: tests are in-process round-trips; KMS uses injected clients.
- Only hard environment requirement: **ext-sodium** (AEAD/Ed25519). No real KMS or network needed for `composer test`.
- Conformance fixtures: `docs/fixtures/v3/` (`keys/`, `primitive/`, `wire/`, `negative/`) + `docs/fixtures/v4/`, loaded via `tests/Conformance/FixtureLoader.php`; generated deterministically by `tools/generate-protocol-fixtures.php`. Node/Go SDKs are byte-exact against v3.
- CI (`.github/workflows/ci.yml`): 4 jobs — `build` (PHP 8.0–8.3: validate → sync lock → install → `php -l` → PHPStan → PHPUnit), `packages` (laravel/symfony/ci4/slim/cli on 8.2), `node-sdk` (Node 20: `npm ci` + lint + test), `go-sdk` (Go 1.22: `go test`). Coverage only in `release.yml` (pcov → clover.xml).
- `composer.lock` IS tracked in git despite the `.gitignore:5` comment ("ignore for libraries") — `sync-composer-lock.yml` auto-commits it when `composer.json` changes.

This project is indexed by GitNexus as **SecurePayload** (2387 symbols, 6435 relationships, 197 execution flows). ## Always Do

- **MUST run impact analysis before editing any symbol.** Before modifying a function, class, or method, run MCP `impact({target: "symbolName", direction: "upstream"})` when exposed — otherwise fall back to the CLI (`node .gitnexus/run.cjs`, subcommands per the gitnexus-cli skill). Report the blast radius (direct callers, affected processes, risk level) to the user.
- **MUST run `detect_changes()` before committing** (MCP when exposed, else CLI equivalent) to verify your changes only affect expected symbols and execution flows. For regression review, compare against the default branch: `detect_changes({scope: "compare", base_ref: "main"})`.
- **MUST warn the user** if impact analysis returns HIGH or CRITICAL risk before proceeding with edits.
- When exploring unfamiliar code, use MCP `query({query: "concept"})` to find execution flows instead of grepping (CLI alternative: gitnexus-cli skill). It returns process-grouped results ranked by relevance.
- When you need full context on a specific symbol — callers, callees, which execution flows it participates in — use MCP `context({name: "symbolName"})`.

## Never Do

- NEVER edit a function, class, or method without first running `impact` on it.
- NEVER ignore HIGH or CRITICAL risk warnings from impact analysis.
- NEVER rename symbols with find-and-replace — use `rename` which understands the call graph.
- NEVER commit changes without running `detect_changes()` to check affected scope.
